Why it is built this way

01

Your files never leave the device

Hashing, zipping, compressing, encrypting, stripping EXIF — all of it runs in the page. There is no server to upload to, which is the only privacy guarantee worth trusting.

02

One file, no supply chain

No CDN, no npm install, no font request, no analytics tag. The ZIP writer, MD5, CRC32, the panchang and the AES envelope are written out inside the file rather than pulled in.

03

Works where the internet does not

Clinics, classrooms, a train, an old laptop kept offline on purpose. Save the file once and it keeps working, forever, on anything with a modern browser.

04

Fast to find things

Press Ctrl K and search all 402 tools at once, ranked so the obvious match comes first. Pin what you use often; recents are one tap away.

05

Checked, not assumed

A jsdom suite loads the real file, renders every tool, walks every route, and pins the ported astronomy and crypto to published reference values. It runs on every push.

06

Honest about limits

The panchang says it is approximate. MD5 says it is for legacy checksums only. The calculators say they are not medical, financial or legal advice. Nothing pretends.

What it refuses to do

No network calls. Not for updates, not for fonts, not for analytics. The test suite fails if a fetch, XHR, WebSocket or EventSource appears anywhere in the file, or if any external src or href is added.

No silent uploads. Files are read with the browser's own FileReader and written back with a download — there is no endpoint to send them to.

No account, no telemetry. There is nothing to sign into and nothing being counted. Whatever a tool remembers lives in this browser's local storage and can be exported or erased from Productivity → Backup & Restore.
